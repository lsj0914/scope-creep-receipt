# 需求加塞账单 / Scope Creep Receipt

**把“顺便加一个功能”变成可以讨论的工作量、费用与日期。**

[在线体验](https://lsj0914.github.io/scope-creep-receipt/) · [English](README.md) · [计算方法](docs/methodology.md)

![桌面编辑器与需求变更账单](docs/demo.png)

一个在浏览器内运行的小型决策工具：录入原计划和新增需求，得到明细账单、变更前后完成日期、受影响任务，以及可讨论的取舍。无需账号、后端或 AI API。

## 具体示例

原计划在 2026 年 10 月 5 日开始：范围与设计 12 小时、搭建预约页面 12 小时、测试与交接 6 小时。每天每个任务可用 6 小时，顺序执行，共 5 个工作日，10 月 9 日完成。

临时要求在搭建完成后、交接之前增加一个 12 小时的 CSV 导出功能。按每小时 75 美元、缓冲 0% 估算：

- 新增人工费用 **900 美元**。
- 完成日期变为 **10 月 13 日**，增加 2 个工作日。
- 被推迟的是“测试与交接”任务。

另两个示例展示不同结果：并行的数据字典增加费用但不延后交付；工作坊增加直播后，延期可选的社交媒体素材可以保住原日期。

## 操作方式

1. 加载示例，或新建项目。
2. 设置开始日期、承诺日期、每日可用小时、人工费率和工作量缓冲。
3. 编辑原计划，勾选前置任务；可延期任务可以作为后续取舍选项。
4. 编辑新增需求，设置“在这些任务后开始”和“阻塞哪些原有任务”。
5. 查看账单、工期对比、受影响任务与关键任务。
6. 比较接受新日期、增加每日小时数、延期可选范围。
7. 下载或复制 Markdown 账单；使用“打印 / PDF”保存 PDF；导出 JSON 项目文件以便恢复。

支持英文/中文切换、手机布局、键盘导航、浏览器自动保存、错误提示和三个可导入的[示例文件](examples)。

## 估算边界

任务工期 = 工作量 × (1 + 缓冲比例) ÷ 每日可用小时，向上取整到完整工作日。前置任务全部完成后，后续任务才能开始。费用为新增工作量与缓冲对应的人工费用。

**每日小时数是每个并行任务各自可用的时间，不是全团队共享的总工时。** 模型不进行人员分配，不处理资源冲突。原计划和变更后计划使用相同的当前假设；修改每日小时数时，两份计划一起重算。

仅计算周一至周五，不排除公共假期。缓冲是估算余量，不代表统计置信度。不计算税费、固定成本或延期罚金，日期也不等于实际交付承诺。

## 数据与保存

应用不会把输入发送到 API；草稿保留在当前浏览器的本地存储，除非主动下载、复制或打印。GitHub Pages 负责提供静态页面，正常的访问请求仍会发生。共享浏览器内的本地存储不是加密保管库。

无效的中间输入会留在当前页面，但不会覆盖最近一次有效草稿。界面会标记“草稿未保存”，并暂停导出。建议下载 JSON 保留可携带的副本。无法打开的已保存草稿会保留原文，允许下载原始文件，只有明确选择替换后才会覆盖。项目及导入文件上限为 250 KiB；导出使用紧凑 JSON，保证可重新导入。

## 本地运行与验证

使用 Node.js 22 LTS（22.12 或更高）或 Node.js 24 及以上。

```bash
npm ci
npm run dev
```

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run check
```

TypeScript 与 Vite 构建；Vitest 验证人工推算的计算样例；Playwright 检查桌面、手机、编辑与实际导出结果；axe-core 检查默认界面的无障碍问题。具体算法与限制见[计算方法](docs/methodology.md)。
